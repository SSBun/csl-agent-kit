# Develop 模式

目标：生成一份可长期复用的当前状态地图，使陌生开发者或 Agent 能说明 scope 的职责，按功能理解模块，并沿核心流程定位状态、失败出口和代码入口。

## 报告顺序

### 1. Scope Summary

先记录：

- `Scope`：仓库相对路径；project 写 `.`。
- `HEAD`：commit SHA 或 `unborn`；为 `unborn` 时紧接着声明“本地图完全基于尚未提交的工作树内容，不代表任何 revision”。
- `Working tree`：`clean` 或“包含本次分析读取的未提交改动”。
- `Generated at`：带时区时间。

`HEAD: unborn` 时，必须紧接说明本地图完全基于尚未提交的工作树内容，且没有伪造任何 revision。

随后用最短完整描述回答：服务哪个用户/调用方；承担什么职责；接收什么输入；交付什么结果；明确不负责哪些相邻职责。组件只说明其对项目的贡献。

### 2. Domain Glossary（可选）

只收录会改变开发判断的项目词：普通义与项目义不同、易与相邻概念混淆，或直接决定职责/状态/流程。

```markdown
| Term | Meaning here | Not the same as | Evidence |
| --- | --- | --- | --- |
```

没有符合项就省略，不生成类型词典。

### 3. Functional Module Map

按最高层功能职责划分，不按目录、package 或文件类型划分。utility、adapter 与内部实现默认并入所属职责；只有具备独立职责、明确边界、状态/领域所有权或核心流程阶段时才单列。一个目录可拆为多个模块，多个目录可合为一个模块。

必须同时包含：

1. **恰好一张 Mermaid 关系图**：只画模块与直接外部系统间的调用、数据或事件方向。
2. **一张职责表**：只写语义，不重复图中的边。

```markdown
| Module | What it does | Inputs | Outputs | Owns | Code anchor | Tests |
| --- | --- | --- | --- | --- | --- | --- |
```

- `Tests` 只列直接验证职责的测试；无法可靠映射时写 `未确认`。
- 不把风险、改进建议、完整依赖/API/类型/文件清单混入 Module Map。

### 4. Core Working Flows

只保留直接实现主要价值、跨多个功能模块，或包含重要状态变化/外部边界/异步协作的流程。每条用相同紧凑骨架：

```text
触发 → 输入 → 模块路径 → 状态变化 → 输出
                         └→ 主要失败出口
```

用短编号步骤从真实入口追到可观察输出。每个关键步骤就地写模块职责与代码入口；只有确实改变状态或受规则约束时才写状态/不变量；只有存在直接证据时才写测试锚点。不要另建重复的代码、状态、失败或测试清单。

### 5. Cross-flow Invariants（可选）

只写同时约束多个模块/流程且无法放入单个步骤的规则。每项含规则、执行位置、违反后果和代码证据；没有则省略。

## 取证顺序

1. 从用户可见行为或上游调用确认 Scope Summary。
2. 沿 import、调用、事件、状态所有权和外部边界识别功能职责；不得从目录名直接推断。
3. 从入口到输出追踪核心流程，核对正常路径、主要失败出口和状态变化。
4. 最后提取必需术语及跨流程不变量，并检查 scope 泄漏、重复和无证据主张。

## Mermaid 交付门

交付前必须使用仓库或环境中**已经存在**的本地只读 Mermaid parser/renderer，对最终图做真实解析或渲染检查：

- 不安装依赖，不使用网络服务，不把“代码块存在”当作验证。
- 验证命令不得修改项目状态；优先经 stdin 验证内存内容。
- 没有可用验证器或验证失败：不创建、不更新目标报告；最终回复只报告零写入阻塞。

## 排除项

不生成第二份 guide、逐模块子报告、依赖版本、Git 历史、完整 API/数据/类型 inventory、代码质量/安全/性能/架构风险、改进建议或特定改动计划。

## 交付自检

- 一 scope、一报告、正确路径和 freshness。
- Summary 准确回答“做什么”；模块按功能，图写关系，表写语义。
- 流程覆盖核心价值、状态、主要失败和就地证据。
- 可选章节无空壳；项目事实均由锚点支持。
- Mermaid 已真实验证；报告无秘密、审计或 inventory 内容。
