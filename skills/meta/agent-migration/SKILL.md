# Agent Migration

协调旧项目或用户数据的目录路径迁移与新版 Memory 系统迁移。通过 `task` 激活任务并遵守其对齐协议；不得将发现旧目录、旧版本或收到检测结果视为迁移授权。

## 默认执行与范围

用户明确调用本 Skill（包括裸调用）且未限定模式、分支或作用域时，即授权对当前工作区执行 **Memory 系统迁移和 `.csl-agent-kit` 目录迁移**。通过 owning Task 管理这一个组合结果；按 Task 当前模式完成必要对齐后，先预检，再连续执行适用且就绪的分支，不能只交付盘点、计划或 dry-run，也不再询问“迁移哪一类”或重复索要同一范围的执行授权。

显式限定优先：只读检查／预览不写入；只迁移目录或只升级 Memory 时不扩大到另一分支；指定其他项目或 user scope 时仅处理该范围。仅加载本 Skill、普通启动或检测到旧结构不构成明确调用，不启动迁移。用户要求先检查再停下时，按其要求暂停。

## 预检与分流

**任何迁移写入之前**，先完成[Memory 目标结构预检](references/memory-migration.md#核对最新目标结构)：读取当前可用的最新权威规范，核对 store/entry/index 版本、project/user 布局及已安装升级器和读写方能力，再盘点实际数据。不能依据本参考中的历史版本号或目录名猜测最新版。单独目录迁移也需检查与 Memory 的源路径和恢复材料依赖，但不因此执行未授权的 Memory 升级；无法核实依赖时阻止受影响项。

逐项报告需要迁移、已就绪、不适用、冲突或受阻，不能把两类迁移合成一个“已完成”标志。

- **目录路径迁移**：读取[统一存储规范](references/storage.md)，执行下述目录流程；目标位置存在不代表所有读写方已切换。整棵 Task 树切换另读[Task 根迁移](references/task-storage-migration.md)，使用已核实的交接机制，不手改历史摘要。
- **Memory 系统迁移**：按[Memory 迁移流程](references/memory-migration.md)复用现有升级器导入其支持的旧知识、转换格式并建立当前scope的索引；不自行复制成第二个知识库。
- **组合执行**：先核对各分支的数据依赖。Memory分支按当前内容模式转换，不自动导入旧源，不创建备份或保留历史；通用目录分支仍遵守其自身保护规则，但不得复制Memory历史或恢复资料来绕过清理要求。已是目标状态的分支只验证；任一分支受阻时可完成不受影响部分，不能宣称整体完成。

## 边界

- 项目目标根是 `<workspace>/.csl-agent-kit/`；用户目标根是 `$CSL_AGENT_KIT_HOME`，默认 `~/.csl-agent-kit/`。项目请求不自动授权用户级或其他项目的修改。
- 仅迁移证实由 Kit 管理的内容；不整体移动 `.agents/`，不移动技能源码、宿主发现入口、第三方内容或无所属权证据的文件。
- 本 Skill 是协调流程，不代表已提供通用目录迁移 CLI。Memory分支使用核实的当前内容转换命令，遵守scope、锁、当前hash和知识保真检查，不创建历史或恢复机制。下文通用目录流程的备份与回滚要求不适用于Memory当前内容转换。
- 不因加载本 Skill 安装启动 Hook，或重复宿主已完成的 Memory 升级。明确调用按上述默认组合范围执行，保留 Task 必要门禁、用户暂停要求及实质冲突决策；project 范围不扩大到 user。共享服务操作还须核对其他工作区影响。

## 目录路径迁移流程

1. **盘点**：只读识别实际工作区、用户数据根、旧源、新目标、符号链接、权限、活动写入方和关联引用。按存储规范列出全部候选类别；对缺失、已迁移、冲突和不支持项分别标记，不能仅迁移 SOP 就宣称全部完成。
2. **检查兼容性**：核对实际安装的读写方均支持目标路径，包括 CLI、宿主发现与注入、面板、关联恢复机制及相关后台服务。若不支持，停止相应迁移并报告升级条件。禁止用双写、符号链接或永久旧路径回退掩盖不兼容。
3. **建立清单**：在目标根的 `migrations/<migration-id>/` 保存中文清单，逐项记录源、目标、所属权证据、类型、大小、SHA256、权限、引用影响及处理结果。备份与日志也在该目录；不保存凭据或不必要的私密正文。清单纳入隐藏文件，符号链接只记录且不跟随，路径不得越出已授权根。无写权限时不迁移。
4. **预览与对齐**：展示精确迁移范围、目标冲突和源清理后果，遵守 Task Target 与实际运行模式。内容相同也要核实关联和权限；不同内容不得覆盖或按修改时间选胜者。任何实质冲突先取得用户选择；SOLO 也不能替用户编造数据保留意图。
5. **冻结写入**：与活动任务和后台写入方协调，采用其支持的暂停或锁机制。无安全暂停能力则停止，不能擅自终止独立服务。若范围包含本次迁移任务或其证据，必须先核实任务核心及宿主 focus 支持迁移交接，并把完成迁移后的记录定位与验证方式纳入清单；能力缺失则阻止 Task 子树切换，不得跳过活动记录却声称全部迁移。复制前重新校验清单；漂移即重新盘点，不使用陈旧授权范围。
6. **备份及复制**：保留可恢复的源副本与元数据，先复制到目标根内独立暂存区，逐项校验内容、权限与类型，再通过经核实的原子 no-replace 操作发布；同名目标在最后检查后出现也必须失败，不能使用会覆盖目标的默认 rename。若所在文件系统无此能力，停止发布。每步记录成功、失败和未决状态；失败保留源及恢复材料，不宣称跨文件操作具有事务性。
7. **修复引用**：仅更新清单内允许修改的活动配置和可变引用。保留内部相对结构；Task ID、Topic 关联、审查报告及快照身份不得凭空重建。不可变历史证据不直接改写；路径绑定失效而组件无合法迁移能力时，停止该项并恢复原状态。
8. **验证切换**：使用非破坏性检查确认实际读写方读取新位置，核对文件数、摘要、权限、索引、链接、Task/Topic 关联与证据可验证性。检查不能越权运行测试。仅存在目标文件或通过 Skill 静态检查不证明运行时切换成功。
9. **清理及恢复**：仅在上述验证通过且符合当前确认模式的破坏性操作边界后，删除清单中已验证迁移的源文件；目录仅在确认为空时移除。恢复写入方并复核无旧路径再生。保留迁移日志和恢复材料，不自动过期删除。

## 目录分支的中断、回滚与完成

恢复时先读清单并重新观察源、暂存区、目标和运行时状态，不能根据上次日志盲目重试。已一致的项只验证；冲突或未知外部写入停止。回滚先暂停相关写入，对比迁移后新增数据，保留差异，不以旧备份覆盖新的用户修改；恢复原数据和读写配置后再验证。无法安全回滚时列明未恢复项、备份位置与所需决策。

完成必须满足：所有批准项已迁入且验证通过；无未解决冲突或悬空引用；源清理结果明确；服务恢复且无旧位置写入；恢复材料可用。部分成功只能报告部分迁移，不能完成整项任务。最终区分已迁移、未迁移、保留项及原因，记录证据与未执行检查。

Memory 分支按其专属流程验收，不套用目录分支的旧源删除步骤。组合任务须分别列出两类结果、保留项和未解决项；目录迁移成功不证明 Memory 格式可用，Memory 升级成功也不证明 Task 等目录已经切换。

## 维护验证

修改本包后运行 `skill-quality`；[触发示例](evals/trigger_cases.json)表达路由边界，[行为案例](evals/migration_cases.json)表达默认执行、结构预检及限定范围的预期，均不证明真实迁移安全或模型已按流程执行。保持存储规范、Task 消费方与宿主注册一致，不将静态检查报告成实际迁移验证。
