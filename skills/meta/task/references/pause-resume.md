# 暂停与恢复

`Paused` 表示主动搁置、以后继续。`Blocked` 表示存在实际阻碍；`Cancelled` 表示停止该任务。暂停保留原任务身份、目标、部分结果和审查义务，不代表完成，也不触发 Git stash、提交、上传或云同步。

## 识别暂停意图与当前状态

先读取[任务状态转换](../../csl-tasks/shared/protocols/task-state-transitions.md)，尤其是仅维护已有任务状态分支。任务管理语境中的 pause、suspend、stash、暂存、搁置、先放一放、先做别的统一走 Paused；没有 Suspended 状态。不得将任务改成 Pending 后声称已经暂停，也不得仅停止 Agent 执行就报告状态已保存。Git stash 和操作系统挂起进程不是本流程。

用户仅要求暂停时，先读取并 focus 原任务，保持当前状态，不先 resume/reopen、不创建新任务或实施目标。Pending/In Progress/In Review 可继续下列保存流程；已有 Paused 只回读并报告原保存时间，Blocked 保留解阻条件，Cancelled 保持停止，Completed 不自动重开。不要为了获得可暂停状态而恢复或重开任务。

## 按任务名称定位

用户不需要先取得任务 ID。可以说“暂停〈任务名称〉”或“恢复〈任务名称〉”；Agent 在用户指定的工作区查找原任务，内部仍用原 ID 维护身份、focus、证据和索引，不能因用户使用名称而创建另一个任务。

- `find "名称或关键词" --json` 只读查找标题或 ID 中包含关键词的任务，返回名称、状态、状态时间（`statusAt`）和内部 ID。用户只记得部分名称时，Agent 展示候选，并让用户按完整名称或候选序号选择；即使关键词只有一个候选，也不直接执行暂停或恢复。
- `show "完整任务名称"`、`pause "完整任务名称" --input <checkpoint.json>` 和 `resume "完整任务名称"` 支持唯一完整名称。匹配采用 Unicode NFKC、合并空白及忽略大小写；不做拼写纠错或语义猜测。
- 同名任务有多个时，命令拒绝操作并给出编号、名称、状态、状态时间和 ID。Agent 展示这些信息；必要时只读查看各任务目标来帮助区分，用户可回答“第一个”，不要求用户手工复制 ID。选择仅适用于刚展示的候选；候选变化或选择不明时重新核对，不沿用旧序号。
- 完整名称不存在时，不创建新任务、不自动选相近项。返回候选或说明未找到，待用户选择后用确定的内部 ID 继续。当前工作区没有原记录时，明确说明查找范围，不自动跨项目操作。
- 精确 ID 保留原行为，并优先于恰好与该 ID 相同的另一任务名称。若两者冲突，Agent 使用只读 `find` 展示候选，用户选定后用其内部 ID 操作。
- 名称查找先读取标题，只完整解析匹配记录，避免无关任务的状态格式错误中断查找。匹配任务格式错误、标题无法读取或文件不可访问时明确报错，不能把读取失败当作未找到或静默丢弃候选。普通 `list` 的全量校验行为不变。
- 用户说“暂停当前任务”时，优先核对本会话已 focus 的原任务；没有可靠 focus 时只读查找或询问，不能猜测。名称解析仅确定对象，不跳过暂停摘要、恢复现场核对及已有授权边界。

## 暂停

用户要求暂存任务、先做别的工作或以后继续时，在切换前执行：

1. 核对实际停止点。把尚未落盘的重要事实记入 Execution Log，更新当前 Plan、Decisions 和已有 Result。实现但未验证的部分只能标为未验证，不能提前勾选 Target。
2. 准备以下 JSON 恢复摘要。每个字段都是非空字符串；不存在的内容明确写“无”，未知事实明确写“未知”并说明如何核对。不能把示例文字当作真实进度。
3. 运行 `pause <id> --input <checkpoint.json>`，然后 `check <id>`。临时输入文件仅用于传参，完成下一步回读核对后再删除；原任务的 `Resume Context` 是唯一当前恢复摘要。若输入文件本身是用户要求保留的产物，不删除它。
4. 运行 `show <id> --json`，回读状态确为 Paused、八项 `resumeContext` 与本次输入一致，并以 `check <id>` 确认索引一致，才报告暂停成功。不要只检查摘要存在或依赖聊天记忆；若回读失败或不一致，核对实际文件并说明未保存范围，不能声称已完整暂停。

```json
{
  "progress": "实际停止点、已完成工作与相关 Plan 节点；说明哪些操作尚未完成。",
  "results": "部分成果、文件及证据位置；用工作区相对路径、任务相对链接或稳定外部标识。",
  "verification": "实际执行的检查及结果、未执行检查、未验证行为与证据局限。",
  "remaining": "未完成事项、已知问题、外部操作的未知结果及继续前的核对要求。",
  "decisions": "影响继续工作的已定决策、约束、用户要求；引用必要的权威资料。",
  "nextAction": "恢复后第一项具体动作及其前置条件。",
  "dependencies": "仓库身份、分支、提交或内容身份、未提交和未跟踪改动归属；必要工具、版本、外部资源和权限需求。",
  "transfer": "跨电脑必须携带的任务记录、相关产物、未提交改动及未跟踪文件；哪些已经转移、哪些尚未转移或未知，及取得方式。"
}
```

CLI 的 `suspend <id-or-title> --input <checkpoint.json>`、`stash <id-or-title> --input <checkpoint.json>` 是 pause 的别名，执行相同完整性检查并写入 Paused，不执行 Git stash 或进程挂起。普通 `status <id> suspended`/`status <id> stashed` 会拒绝并提示使用 pause。

摘要保存为 `task-resume-context/v1`。字段值使用 JSON 字符串转义，多行内容不会变成任务章节或状态。CLI 检查字段完整性，不替 Agent 验证语义、文件存在、传输完成或授权。`show <id> --json` 和 `resume <id>` 返回结构化 `resumeContext`；普通 `show` 返回包括原始章节的完整任务文件。

仅 Pending、In Progress、In Review 可以暂停。Blocked 保持阻断，不能通过暂停去掉阻断条件。Paused 只能恢复到 In Progress 或取消；不能直接进入审查、待执行或完成。只有用户明确恢复、完成正常恢复核对并再次请求暂停后，才保存新的摘要；不得为重复暂停而自动恢复任务或无意沿用旧停止点。暂停及恢复失效当前验证和审查评估，保留 Required 审查义务及未解决 finding；不会自动把未解决问题清零。

## 全新会话恢复

在用户指定工作区打开原任务；按任务的目标对齐和激活流程继续。读取 `Resume Context`、Target、Plan、Decisions、Execution Log、Result 和适用的 Block、审查记录，不能只读取摘要或最后一条日志。

先只读核对仓库、代码版本、文件和外部操作状态。对未知操作结果先查证再重试，不能把“没有日志”当作“未执行”。从暂停恢复到 In Progress 只表示重新激活，不证明现场已还原，也不授予新的执行权限。目标保持不变时遵守既有目标接受证据的恢复规则；摘要不创造接受证据。

用户明确要求恢复后，完成必要的现场核对；满足前置条件才执行后续动作。发现必要代码、产物、凭证或权限缺失时，记录具体缺口与可观察的恢复条件并 Block；完成不依赖缺口的获准核对，不能假装已有完整工作内容。恢复后保留上一份摘要作为有日期的历史停止点；当前进展以更新后的计划、日志、结果和现场为准，下次暂停替换当前摘要。

## 换电脑

记录可移植不等于所有工作内容自动同步。先按当前活动存储布局取得原任务记录及索引、所需任务产物、关联 Topic 与固定规范（如有）、代码和未提交成果。不要迁移或双写数据根来完成普通恢复。

- 记录项目内文件时使用相对路径，并写明相对哪个根。仓库以身份及版本定位，不能只靠旧电脑的绝对路径。
- 本机外部资源必须说明用途、旧位置及重新取得或配置的方法；绝对路径只能作为旧机器线索。
- 已有改动未提交时，写清要携带的文件或补丁位置。单独复制任务 Markdown 不能恢复未转移的代码。不要自动创建补丁、提交、推送、上传或复制凭证来假装完成转移。
- 先核对文件和内容身份，再刷新受机器路径或工作区状态影响的证据与快照。旧检查结果只能说明旧环境观察，不能直接证明新环境通过。
- 不在记录里保存密钥、访问令牌、完整隐私日志或隐藏推理。只记录所需权限和安全取得凭证的方法。

Queue 暂停不递归修改子任务，也不替仍在运行的子 Agent 停止执行。先停止或收束实际写入方、确认未知外部操作，再分别为实际暂停的活动子任务和父任务保存摘要。恢复保持 `next` 返回的顺序；Paused 子任务不能跳过。普通独立任务之间切换不建立 Queue 关系。
