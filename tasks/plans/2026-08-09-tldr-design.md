# TLDR Skill 设计

## 状态

已确认，可作为后续实施的决策依据。

## 核心职责

`tldr` 接收用户传入的任意对象，获取形成可靠认知所需的最少信息，并提供简洁、准确、可快速理解全貌的 overview。

主题、会话、项目、远程链接、文本、代码或其他内容都只是可能的输入示例，不构成封闭分类。Skill 不维护固定的类型路由表，而是根据目标自身决定需要读取什么、哪些结构最重要，以及如何用最短输出表达整体。

## 目标解析

- 用户明确传入目标时，以该目标为准。
- 用户未传入目标时，总结当前话题段，即从最近一次明显的任务或主题切换开始的可用会话。
- 只有目标存在实质歧义时才询问一个必要问题，不猜测用户意图。

## 信息获取

- 使用宿主已有的文件、Git、网页和会话能力，不新增脚本或依赖。
- 对本地或远程对象，只获取形成 overview 所需的内容。
- 对只有名称的主题，优先使用 Agent 已有知识；涉及时效性或不确定事实时执行最小必要检索。
- 不默认完整扫描项目，也不把 overview 扩展成深度研究。

## Overview 构建

Agent 应识别目标是什么、目的是什么、主要组成或方面是什么，以及当前最重要的信息是什么。这些是思考维度，不是固定输出字段。最终结构应服从目标自身，而不是套用输入类型模板。

Overview 必须忠实区分来源事实、明确结论和未知信息。不得主动加入原内容不支持的建议、审查判断或推测。

## 输出契约

默认输出控制在一屏内：中文通常约 150–350 字，其他语言保持相当的信息密度；简单目标可以更短。

建议形式：

```markdown
**TL;DR:** 用 1–3 句话说明对象是什么、核心价值或当前结论。

- 最重要的组成、方面或上下文
- 核心关系、流程或发展脉络
- 理解该对象必须知道的状态、约束或结果
```

该形式不是固定模板。使用尽可能少但足以形成整体认知的要点，通常不超过五个。优先表达结构和关系，不堆积孤立细节，不重复信息，也不追加建议、教程或惯例性的“是否需要更多帮助”。

输出语言跟随用户；代码标识符、命令和专有名称保持原样。使用检索内容时保留简洁来源链接；只读取部分目标时说明覆盖范围。默认在会话中输出，仅在用户明确要求时保存文件。

## 失败行为

- 目标不存在、为空或无法访问：明确说明，不生成虚构 overview。
- 目标过大：选择最具代表性的权威内容，并披露覆盖范围。
- 多个目标存在实质歧义：只询问一个必要问题。
- 远程内容需要登录、权限或受到访问限制：说明未读取到正文，不以搜索摘要冒充原内容。
- 信息来源冲突：呈现冲突，不静默选择。
- 时效性事实无法验证：明确标记不确定性。

## Skill 包与集成

使用最小叶子 skill：

```text
skills/tldr/
├── SKILL.md
├── agents/
│   └── interface.yaml
└── evals/
    ├── semantic_config.json
    └── trigger_cases.json
```

`SKILL.md`、runtime prompts、接口元数据和 eval-facing prose 使用英文。不增加 scripts、references、子 skills 或新依赖。`agents/interface.yaml` 仅承载仓库跨平台打包校验要求的最小接口元数据，不参与运行时处理。

实施时只更新必要入口：Claude 的显式 skill 清单、README skill 表和 Pi alias 测试。Codex、Cursor 与 Pi 继续使用现有递归发现机制，不修改无关 marketplace、keyword 或安装逻辑。

## 验证

- 正向路由覆盖明确调用 `tldr`、要求任意目标 overview，以及未指定目标时总结当前话题。
- 负向路由覆盖深度研究、代码审查、完整项目分析和教程请求。
- 验证 Pi `/tldr` alias、项目测试、Yao skill 校验、resource boundary check 与 `git diff --check`。
- 由于没有可执行逻辑，不增加单元测试脚本。
