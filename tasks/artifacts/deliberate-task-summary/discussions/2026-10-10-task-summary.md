# 任务摘要应保留什么

建议把完成总结定位为**回看入口，而不是任务缩写**。默认它与完整任务正文一起阅读。

只补充“不写下来，下次就得重新查找或推断”的信息：
- **改了哪里、意味着什么**：按组件根目录写简短变化，不列内部文件、不复述操作过程。无文件改动时写实际产物或结论入口。
- **需要记住什么**：只留影响后续工作的选择理由、适用边界和仍然存在的限制；已有 Decisions 记载的，用简短指引，不再复制。
- **回来从哪看**：仅在入口不明显时指出关键证据或继续工作的起点；没有具体用途就省略，不固定附上“后续建议”。

**不必另写一段结果综述，但应保留现有 Result 验收证据和 Verification 检查记录。** Target 已说明目标，Plan 已说明路径；总结不再抄目标、计划或勾选项。涉及验证时指向原记录，不扩大“已验证”的范围；遗留事项应区分“不在范围内”和“尚未解决”，不能包装成已完成。

不选完整文件清单或独立长报告：它们适合脱离任务正文的交接，不适合这里的快速回看。也不把所有信息硬塞进固定栏目：已有内容足够时，总结可以省略。

**示例（仅示意，不代表已实施）**：
> 回看：任务组件 ["/Users/caishilin/Desktop/personal/skills/skills/meta/task"](file:///Users/caishilin/Desktop/personal/skills/skills/meta/task) 的完成总结改为按需补充回看线索，验收证据仍留在 Result，检查记录仍留在 Verification。为避免重复，不增加独立结果综述；理由见 Decisions。本次仅涉及任务组件，不涉及规划组件。若以后调整完成记录结构，从该组件的完成规则和 Result 约束看起。

例中的理由、边界和重入提示都不是必填项；若正文已有清晰入口，就删去对应句子。

## 适用范围与限制

- 推荐基于总结与完整 canonical task 同处阅读；若要求独立交接，需要重新评估必要上下文。
- 保留 Result 证据与省略重复结果综述是不同决定；精简总结不削弱验收或验证记录。
- 独立 Synthesizer–Challenger 讨论已收敛，无未解决的实质问题。字段职责由主 Agent 核对现有 Task 契约，两角色依赖提供的来源摘要，未独立复核原文。
- 本次仅形成建议，未修改工作流规则或实现，未运行测试。
