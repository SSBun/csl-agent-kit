## Scope

用户已确认实施Target：建立隔离合成语料、答案和最小运行器，执行36次真实模型试跑，报告质量、实际用量和正式阶段费用估计。只运行本实验及必要验证，不运行无关项目测试；不改变正式Memory数据或实现、不发送真实记忆、不自动重试失败请求。432次正式实验须在试跑报告后另行确认。比较只读检索，不评估写入并发、迁移和维护质量。

## Decisions

### 假设与对照

不预设赢家。A为现有按字符预算分页的Markdown索引（每页4000字符，包含续页链接）；B为单个完整Markdown索引，允许普通文件工具搜索和分段读取。两者保留相同条目顺序、标题、摘要、type、revision及hash，不借机删掉B中的元数据。正文文件、事实与工具能力完全相同；允许两组使用read/grep/find，不把A人为限制为只能翻页。续页元数据及路径差异是表示方式的必要差异。

主实验仅向两组提供索引入口路径与同样的通用检索指令，不预加载索引正文，以隔离索引表示方式。不得给A更低效的操作教程，或给B额外关键词提示。工具默认分页、输出截断上限、工作目录可见性、模型上下文限制均保持一致。每组只可见所属语料，不可访问另一组或答案文件。

启动注入作为独立的后续实验，不混入主结果：比较当前A首页注入与拟议B仅提供路径的真实策略，明确变化包括启动提示量，因此不能把结果只归因于文件分页。索引生成耗时、文件数和字节量单独报告，不混入模型检索延迟。

### 数据与答案

使用确定性生成的合成知识，避免真实用户资料及模型已有常识泄漏；事实值使用无外部常识可推断的虚构标识与关系。准备50、200、1000个文件的三个规模，以及两个作用域；同一基础问题所需事实跨规模保持一致，仅增加干扰资料。

设计24个问题模板，6类各4个：精确名称查找、同义/语义查找、跨文件综合、同名不同适用范围、用户/项目范围限定、知识不存在时拒答。综合类要求读取2—4份正文，范围类设置看似相关但不适用的干扰内容。必要资格条件只放正文，防止读索引就蒙对。

每题预先冻结gold：必要事实、必要来源ID、可接受等价表达、适用范围、禁止混淆事实、是否应拒答。主要评分基于结构化最终答案和来源，不把访问过文件等同于使用正确。多来源替代支持允许预登记等价来源集合，不以命中单个指定文件作为唯一标准。

用固定种子改变条目顺序，同一配对A/B完全一致；将目标位置平衡覆盖索引前、中、后部。两个作用域的相关条目都要覆盖。随机种子、语料hash、生成器版本与题目集在运行前冻结；不按实验结果修改gold或删难题。

### 运行方案

每个请求使用独立、无历史会话；不得复用正式Memory Agent会话、开启后台写入或读取真实记忆根。固定provider/model精确版本（可用时）、thinking、采样设置、SDK、工具实现和最大输出。禁止子Agent及网络检索。语料只读，答案写结构化结果而非修改记忆。

试跑选每类1题，覆盖三种规模及两种方法，共6×3×2=36次请求，仅用于校验题目、埋点、阈值和估算成本。正式阶段使用冻结后的24题×3规模×2方法×3重复=432次请求；不同重复使用预定语料排列，相同配对共用排列。试跑数据不计入正式比较。模型不可完全确定时记录随机性而非宣称seed保证复现。

每次设相同的60次工具调用及180秒上限；这是初始建议，先用试跑核验，若调整须在正式阶段前两组同步冻结。不得只给失败的一组追加预算。配对顺序随机交错，正式请求串行执行以降低限流与并发干扰；记录时间段及可观察缓存用量，不声称能够清除provider缓存。

模型错误、工具错误、超时及预算耗尽都进入记录；超时/耗尽计入总体任务失败。基础设施故障另列，同时报告包含故障与剔除配对基础设施故障的敏感性结果。禁止自动重试模型请求；若需要补测，由执行方说明原因与新增成本并另行获得必要授权，原失败记录保留。

### 指标与评分

主要指标为严格任务成功率：所有必要事实正确、适用条件正确、引用支持答案且没有禁止混淆或无依据结论；不存在题须正确拒答。辅助报告必要事实召回率、事实精确率、来源支持率及错误拒答率。非空题与不存在题分开统计，不能通过全部拒答提高精确率。结构化字段可确定性比较，语义边界由对方法标签盲化的人工核对；模型裁判不能作为唯一gold。

成本报告实际input/output/cache token明细，以及可获取时的reasoning token；不可获取字段标为未知，不由字符数冒充token。另记录工具返回字符/字节、read/grep/find次数、重复读取、端到端耗时及错误类别。按当时价格估算货币成本并标明版本及缓存计费差异。

同时报告全部请求成本、每个成功任务的总体成本（全部尝试成本除以成功数）、同题两组都成功时的配对成本，避免只看幸存成功样本。时间报告中位数与p95，超时数量单列；有删失时不把180秒当实际完成耗时。三个规模及六类题分别展示，防止平均值掩盖后页和语义查询退化。

### 统计与决策

每个题目模板为聚类单位进行配对bootstrap，保留同题的规模与重复关联，给出质量差值和成本比的95%置信区间；重复运行不当作独立题目扩大样本量。24个模板是初始规模，不保证统计功效，正式结果可为证据不足。

预设质量优先：候选方法成功率差值95%区间下界不低于-5个百分点，且不新增关键范围混淆/编造失败，才进入成本优选。随后要求总体每成功任务token成本至少降低15%，且配对成本改善有方向一致证据；延迟为辅助指标，不将provider抖动当结构收益。阈值是拟议工程容忍值，不是已验证事实，执行前必须明确接受或调整并冻结。

若质量差异不明确、区间过宽、不同规模相反或安全/范围类出现退化，结论为不确定或按规模区分，不强行选赢家、不自动修改产品。扩大样本需预先固定扩展批次，避免反复追加直到出现显著结果。实验仅支持所测模型、语料和规模下的结论，不外推为所有Agent的普遍规律。

## Plan

1. 核对实际Memory模型配置和SDK，固定模型与36次试跑上限；每次180秒、最多60次工具调用，明确记录实际token而不伪造未知计费。用户已授权本试跑及必要验证。
2. 编写隔离语料生成与gold，人工核对覆盖、必要资格条件、来源等价和两组信息一致；检查只读路径及无真实资料。
3. 实现最小运行器和JSONL记录；记录case_id、method、scale、seed、repeat、模型配置、语料hash、时长、token、工具统计、结果、错误与逐项评分，令牌/凭证不入日志。
4. 在明确授权后运行36次试跑；锁定提示、工具行为、成本预算、上限和评分规则。试跑后决定是否授权432次正式请求，不默认全部启动。
5. 执行冻结的正式比较，保留失败与原始证据；输出分层质量、成本、延迟及配对置信区间，不先改正式Memory。
6. 根据证据单独决定是否开展启动注入实验、扩大题目集或修改产品；实施索引变更仍需新的授权与目标对齐。
