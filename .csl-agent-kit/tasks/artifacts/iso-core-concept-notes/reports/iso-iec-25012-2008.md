# ISO/IEC 25012:2008：数据质量模型核心概念

## 标准身份与阅读边界

- 英文名称：Software engineering — Software product Quality Requirements and Evaluation (SQuaRE) — Data quality model。
- 版次：2008年，第1版。
- 本文依据ISO公开摘要和公开教学资料提炼概念，未逐条核对标准全文。中文解释不是官方术语译文或完整定义。
- 标准面向计算机系统中以结构化形式保存的数据。将其用于自然语言Memory，是本地类比应用。

## 核心概念

### 1. 数据质量相对于使用目的判断

质量评价需要明确使用者、任务和环境。不同利益相关者对各项质量特征的重视程度可能不同。

例如，分钟级更新的数据可能适合某类统计报告，却不适合实时控制。数据是否“足够新”，应结合用途判断。

### 2. 区分数据内在质量与系统依赖质量

- 内在质量关注数据本身是否具备所需属性，例如准确性、完整性和一致性。
- 系统依赖质量关注运行环境能否使数据按要求被保存、访问、传递或恢复。
- 部分特征涉及两个视角；这不是两个互不相交的清单。

一句知识写得正确，不代表系统能在需要时检索到它；系统始终在线，也不代表返回的知识正确。

### 3. 模型包含15项质量特征

下表为便于理解的简释，不代替标准正式定义，也不声称下列顺序是标准原始排列。

| 特征 | 阅读时应关注的问题 |
| --- | --- |
| 准确性 Accuracy | 数据是否正确表示对象或事实？ |
| 完整性 Completeness | 当前用途所需的信息是否齐全？ |
| 一致性 Consistency | 表达、取值或关系是否相互矛盾？ |
| 可信性 Credibility | 数据是否被认为真实可信，并有相应依据？ |
| 时效性 Currentness | 数据是否足够及时，能够支持当前用途？ |
| 可访问性 Accessibility | 使用者能否访问数据，包括需要辅助技术的使用者？ |
| 符合性 Compliance | 数据是否满足适用标准、约定或要求？ |
| 保密性 Confidentiality | 数据是否只向获准主体开放？ |
| 效率 Efficiency | 使用和处理数据所需资源是否适当？ |
| 精确度 Precision | 数据细节和分辨程度是否满足使用需要？ |
| 可追溯性 Traceability | 是否能了解必要的访问或变化背景？ |
| 可理解性 Understandability | 使用者是否能够正确阅读和解释数据？ |
| 可用性 Availability | 授权使用者在需要时能否取得数据？ |
| 可移植性 Portability | 数据能否在所需环境之间迁移并继续使用？ |
| 可恢复性 Recoverability | 出现规定故障后能否恢复所需数据和使用能力？ |

准确性与精确度不同：更多小数位不保证数值正确。可访问性与可用性也不同：服务在线不意味着所有目标使用者都能有效访问内容。

### 4. 模型、度量和评价结论是不同层次

模型提供共同词汇，支持制定质量要求和开展评价。实际评价仍需要选定对象、指标、方法和可接受条件。

一个总体分数不能自动证明所有维度合格。没有进行相应检查时，不能把“没有发现错误”写成“已经确认准确”。数据质量度量可进一步参考相关SQuaRE标准，本文不展开未讨论的标准要求。

## Memory应用：本地建议

优先检查准确性、完整性、一致性、时效性和可理解性：

1. 结论是否有当前依据？
2. 是否保留版本、环境、触发条件及例外？
3. 是否与其他案例或当前规范冲突？
4. 前提变化后是否仍可使用？
5. 没有原始对话的人能否理解？

检索可用性、访问控制和资源消耗属于系统层检查，不能只靠改写案例解决。

当前Memory采用“只保存当前知识”的设计，因此不因参考可追溯性或可恢复性而自动添加历史、来源审计或备份。选择应用部分质量原则，不构成完整采用或符合全部标准的声明。

## 常见误用

- 用格式有效代替事实准确。
- 把“存在可信来源”当作无需核对结论的理由。
- 仅因条目较旧而判定失效。
- 给所有维度设置相同权重，却不考虑使用目的。
- 为追求完整模型而擅自改变产品的数据保留策略。
