# ISO 23081-1:2017：记录元数据核心概念

## 标准身份与阅读边界

- 英文名称：Information and documentation — Records management processes — Metadata for records — Part 1: Principles。
- 版次：2017年，第2版。
- 本文依据ISO官方目录及技术委员会说明作概念提炼，未逐条核对标准全文。
- 名称使用Part 1的官方标题；不与同系列其他部分的标题混用。

## 核心概念

### 1. 元数据支持理解和管理记录

记录元数据不只是用于搜索的标题、标签或关键词。它还帮助解释记录与业务活动、主体、管理过程及其他记录的关系。

例如，同一段“批准执行”的文字，只有联系批准对象、相关主体和活动背景，才可能得到正确解释。

### 2. 原则适用于记录、过程、系统和负责组织

官方范围包括记录及其元数据、影响它们的所有过程、保存它们的系统，以及负责管理的组织。

因此，元数据不只是在文件创建时填写几个字段；它还与系统如何持续管理记录有关。

### 3. 内容背景与管理行为都很重要

理解一份记录，可能需要知道它对应什么工作、涉及什么主体、在什么条件下形成，以及经历了什么管理动作。

ISO技术委员会强调，元数据可以帮助说明谁对哪个记录对象做了什么。其目的包括支持真实性、可靠性、完整性和可用性判断。

这些信息是否需要保存、采用什么粒度，应由记录管理目的和要求决定，不是无限增加字段。

### 4. 关系使孤立记录获得含义

记录通常并非孤立存在。它可能依赖某项决定、回应某个请求，或属于某个业务过程。

只保留对象ID而没有可理解的关系语义，未必能帮助使用者。关系信息还需要与实际业务一致。

### 5. 元数据本身也需要管理

元数据若失真、丢失或无法解释，记录的使用和可信判断也会受到影响。应关注元数据的含义、与记录的联系，以及系统变化时这些联系是否仍可使用。

迁移文件字节不代表已经完整迁移了记录背景。反过来，不能仅因为某种数据曾存在，就推断它必须在所有目标系统中永久保留。

### 6. 原则与实施方案分开

Part 1提供原则；同系列Part 2讨论概念和实施问题，Part 3提供自我评价方法。本文只提炼Part 1，不把其他部分内容当作已覆盖。

原则并不指定统一的Markdown前置信息字段，也不要求所有应用采用同一个数据库模型。

## Memory应用：本地建议

当前Memory只保存title、summary及带日期case。可以借用本标准对上下文的关注，在正文中保留影响应用的必要信息：

- 知识适用于哪个项目或组件。
- 是否只对某个版本或环境成立。
- 哪些条件会使结论失效。
- 阅读时是否需要结合其他当前知识或权威规范。

不要仅因参考记录元数据原则，就添加source、owner、revision、关系表或变更审计。当前Memory没有承担完整记录证据管理职责；正式活动背景由Task或其他记录系统按自身要求保存。

涉及文件移动或合并时，应检查当前知识引用是否仍能使用，但不为此恢复已退休的历史存储。

## 示例

缺少背景：

> 重载不会生效。

保留必要背景：

> 对已加载的CommonJS依赖，仅重载Pi扩展不会刷新该依赖的缓存；该结论不自动适用于扩展读取的所有资源文件。

第二种表达给出对象、操作和适用边界。它借用了“上下文支持解释”的原则，不是ISO规定的案例格式或技术结论。

## 常见误用

- 将元数据简单等同于标签或文件名。
- 增加很多字段，却没有明确使用目的和含义。
- 把稳定ID当作业务关系或可信性的充分证据。
- 认为文件迁移成功就证明所有背景关系保持有效。
- 把记录管理的元数据要求直接套用到只保存当前知识的Memory。
