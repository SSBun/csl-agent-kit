# ISO 15489-1:2016：记录管理核心概念

## 标准身份与阅读边界

- 英文名称：Information and documentation — Records management — Part 1: Concepts and principles。
- 版次：2016年，第2版。
- 本文依据ISO官方目录、技术委员会说明及公开介绍作概念提炼，未逐条核对标准全文。
- 本文讨论活动记录及其证据作用；后面的Memory映射是本地应用建议。

## 核心概念

### 1. 记录与活动及其证据需要相关

组织和个人在开展业务或其他活动时形成、接收并保留的信息，可以承担记录作用。记录不限于纸质文书，也可以是数据、电子文档或其他形式。

记录的价值不仅在正文，还在于它能够说明某项活动、决定或事务。没有必要背景，文本可能无法被正确解释。

### 2. 创建、捕获和管理是相关但不同的活动

形成信息不等于已将其纳入受管理的记录系统。捕获意味着让记录进入适当管理环境，并具备支持后续识别、理解和使用的条件。

管理需要延续到记录被使用、保存、转移或按授权处置的过程。具体控制应以业务、法律及其他适用要求为依据。

### 3. 四项重要性质

下表是阅读性解释，不代替标准的正式定义。

| 性质 | 核心问题 |
| --- | --- |
| 真实性 Authenticity | 能否确认它确实是其所声称的记录，并理解相关主体及形成背景？ |
| 可靠性 Reliability | 内容能否作为所涉及活动的可信表达？ |
| 完整性 Integrity | 记录是否保持完整，未受到未经授权的改变？ |
| 可用性 Usability | 需要时能否找到、取得、呈现和理解记录？ |

哈希可以帮助发现字节变化，但不能单独证明记录内容真实。记录能够打开，也不等于相关业务背景能够被理解。

### 4. 业务环境决定记录要求

需要持续分析工作活动、责任、风险及适用要求，识别应该创建和保留哪些记录。不能先选择一个工具，再假定工具默认保存的内容就是完整证据。

记录要求可能随组织活动和环境变化，因此需要复查。

### 5. 政策、职责和控制共同支持记录管理

官方范围包括政策、分配的责任、监测、培训、记录控制及管理过程。记录管理需要组织安排支持，而不是仅依赖个人习惯。

控制可以涉及分类、访问、保留和处置等方面。是否保留、何时处置以及如何处置，需要依据适用要求，不是“所有记录永久保存”。

### 6. 元数据和记录系统保留必要背景

正文与背景信息共同帮助判断记录的含义、关联活动和使用条件。ISO 23081系列进一步讨论记录元数据的原则。

技术系统需要支持这些目标，但标准采取跨形式、跨技术环境的原则性方法，不指定唯一软件或存储方案。

## Memory与Task应用：本地建议

对Task或活动记录：

- 明确区分计划、尝试、工具返回成功及经过验证的结果。
- 保留适合该记录用途的对象、状态、证据和背景。
- 不把未执行的检查记录为通过。
- 对重要决定和结果，确保后续人员能够理解记录所表达的事情。

对Memory：

- 保留可复用结论及必要条件，避免摘要改变原意。
- 需要证明某次活动实际发生时，回到Task或适当证据载体。
- 当前Memory不承担完整记录管理系统职责；不因此新增历史、审批、审计或恢复副本。

这套分工是项目选择，不是标准要求所有系统采用的架构。

## 示例

不充分的记录：

> 发布成功。

更有用的记录表达：

> 已向目标环境发出发布请求，服务返回接受；尚未完成目标版本和健康状态检查。

该表达保留了实际观察与未验证部分。若后续确认部署成功，应由活动记录系统更新结果和证据；Memory则提炼“接受请求不等于部署验证完成”的可复用判断。

## 常见误用

- 把工具调用成功直接等同于业务目标完成。
- 用摘要替代所有原始证据，却仍声称证据完整。
- 把文件存在或哈希一致当作真实性的全部证明。
- 认为记录管理意味着无差别永久保存。
- 将Memory的当前知识策略推广为其他证据系统的删除授权。
