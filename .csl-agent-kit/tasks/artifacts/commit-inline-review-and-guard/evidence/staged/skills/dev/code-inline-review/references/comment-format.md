# 审查说明格式

保留前缀由 `@code` 与 `-review` 无间隔拼接，起止保留字分别为此前缀加 `:begin` 与 `:end`。标记独占注释行，后接相同的 `<组 ID>/<块 ID>`，例如 `cancel-01/client`。组 ID 在当前改动中唯一；每个块 ID 在组内唯一。不要依赖行号建立关联。

下面用 `BEGIN`、`END` 作为文档占位符；生成到源码时分别替换为上述保留字。文档、测试夹具或示例需要描述协议时也用占位符或拆分字符串，避免产生看似待清理的实际说明块。

主块：

```text
// BEGIN cancel-01/client
// 目标：支持用户取消请求。
// 背景：页面退出后请求仍继续执行。
// 方案：由页面创建信号，经 client 传递到 transport。
// 本块：为请求入口增加 signal 参数。
// 关联：cancel-01/transport、cancel-01/ui。
// END cancel-01/client
```

关联块：

```text
// BEGIN cancel-01/transport
// 目标：支持用户取消请求。
// 本块：将 signal 传给 fetch，保持错误传播行为。
// 主说明：cancel-01/client。
// 审查：主动取消不应显示为网络故障，此项尚待验证。
// END cancel-01/transport
```

主块放在最能解释整体意图的位置。关联块可跨文件，通过组 ID 全局搜索。主块移动或删除时更新引用；整个逻辑组撤销时移除对应说明。部分改动提交后保留的说明要注明当前剩余范围，不能继续引用已清理的主块。

支持的注释包装按实际语言选择：

| 语言形式 | 每行写法 |
| --- | --- |
| C/Swift/TypeScript 等行注释 | `// 内容` |
| Python/Shell 等行注释 | `# 内容` |
| SQL/Lua 等行注释 | `-- 内容` |
| Lisp 等行注释 | `; 内容` |
| CSS 等块注释 | `/* 内容 */`，每行各自闭合 |
| HTML/XML 注释 | `<!-- 内容 -->`，每行各自闭合 |

不要创建跨多行未闭合的注释包装；不要嵌套说明块。说明中的内容不能包含该语言的注释终止符或二次起始符。清理预览只检查格式，无法证明这些文本位于真实语言注释中；Agent 必须先排除字符串、模板字面量和文档字符串中的示例。

说明应提供代码之外的信息，而不是把赋值或函数调用翻译成自然语言。长期有效的约束如需保留，应另写普通代码注释；不得通过只删除特殊标记来把整段临时说明混入提交。
