# Code Inline Review

## 启用与范围

默认不生成说明。用户明确调用本 Skill 才对当前授权任务的改动启用；不得因此扩大代码修改范围。沿用 owning Task，不创建另一套任务状态。

“关闭”只停止新增，不隐含删除已有说明；已有说明失效时更新或移除，明确要求清理或准备提交时才执行清理。不要把单次启用变成全局默认。

## 生成与维护

先读 [说明格式与示例](references/comment-format.md)。按逻辑意图分组，而不是机械对应 Git hunk：

1. 每组一个主块，解释目标、背景、方案、本块职责和关联块。
2. 关联块保留一句共同目标、本块职责和主块 ID；必要时补充审查重点。
3. 有独立行为、约束或取舍的改动就地说明。机械透传、导入等集中交代；整文件或模块删除无需单独注释，其他删除在相关块说明。
4. 每个标记区只容纳说明，业务代码始终在标记之外。普通长期代码注释保持原样。
5. 只保存当前解释，问答在聊天中进行。代码变化时同步更新；“待检查”不能写成“已验证”。

仅在支持注释、允许人工维护的源码中插入。标准 JSON、生成文件、二进制和不确定语法的区域不插入；在相关主块或聊天/PR 说明中交代。不要将标记放进字符串、模板字面量、文档字符串或业务代码行尾。

## 清理

本 Skill 只负责说明内容的生命周期；提交检查与阻断诊断由独立的 `commit-guard` 负责。

工作区可以保留说明，只要待提交版本没有说明。不要为了提交无关文件而清理所有说明；不要调用 `git add .` 掩盖部分暂存选择。

准备清理当前授权范围时：

1. 读取工作区和暂存区 diff，确认要清理的块；需要保留到 PR/MR 的解释先存入 owning Task 的讨论 artifact，按实际 Task 存储根管理，不放进源码提交。
2. 运行 `node <skill-dir>/scripts/preview-clean.js <file>`，读取其 JSON 中的原文 SHA-256、删除范围和清理后内容。该命令只输出预览，不写文件或 index。
3. 确认每个区域在对应语言中确实是注释，且属于本任务。标记残缺、嵌套、ID 不匹配、含代码或来源不明时停止自动清理，报告位置。
4. 重读确认原文未变化，再用精确编辑删除确认的说明区。保留其他字节与普通注释；对照预览检查 diff。
5. 仅按用户授权的提交范围暂存。已有部分暂存时保留其选择，不整文件重新暂存；无法确定时报告问题。

远端需要这些说明时，基于实际提交重新核对保存的解释，再按用户授权整理进 PR/MR。第一版不自动发布评论或同步旧说明。

## 验证

确认主块与关联 ID 可搜索且一致，清理只删除确认的说明，普通代码不变；说明不在提交版本中时允许工作区继续保留。路由边界见 `evals/trigger_cases.json`；维护后执行 skill-quality。
