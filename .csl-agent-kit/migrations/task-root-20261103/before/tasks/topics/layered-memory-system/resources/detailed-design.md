## 1. 目标与非目标

### 1.1 两级长期记忆

| 作用域 | 保存的信息 | 维护方式 |
| --- | --- | --- |
| user | 跨项目偏好、稳定工作习惯、通用经验、个人参考资料 | Agent 可提出变更；必须展示具体内容和理由，取得用户明确授权后才能改变有效记忆。 |
| project | 项目事实、架构约束、有效经验、项目参考资料 | Memory Agent 可根据来源自动维护，必须保留理由、差异、审计与恢复能力。 |

记忆保存当前有效知识，而不是把每轮聊天追加成长期摘要。项目重要知识仍属于项目作用域，不因重要就提升为用户级。知识提升同样经过用户级审批。

系统不设置 Core/Normal 权限层。内容类型为 `fact`、`preference`、`experience`、`reference`，仅作描述与检索元数据，不新增分类目录、不改变权限、不因类型不匹配排除相关内容。

### 1.2 全局原则

1. 条目文件是内容权威；索引由 CLI 确定性派生，可随时重建。
2. 先看精简索引，再按需读取正文；两级都不默认全文常驻。
3. 前台任务与后台维护解耦，读取不进入维护队列。
4. 以 revision/hash 条件写入拒绝过期覆盖，避免并发丢失修改。
5. 项目记忆持续整理当前有效内容，变更必须有据、可解释、可恢复。
6. 故障可见；“已入队”“服务已就绪”“已处理”必须分开。
7. 最终完全替代 Context/Lessons 的独立读写维护机制，不保留永久双重事实来源。

### 1.3 非目标

- 不提供操作系统级沙箱，不防护有本机文件权限的进程直接绕过协议。
- 不改变用户启动 Pi 的正常方式，不增加专用 Pi 启动器。
- 不自动迁移 Task、Rules、SOP 或完整任务历史。
- 不未经批准将项目知识提升到用户级。
- 首期不强制向量数据库、embedding 服务或语义检索基础设施。
- 不因为近期未使用就删除知识，不丢弃仍有效的独有信息。
- 首版自动宿主接入仅承诺 Pi；其他宿主后续扩展，服务与存储协议保持宿主无关。

## 2. 组件、职责与数据流

| 组件 | 职责 | 不承担的职责 |
| --- | --- | --- |
| Task Agent | 完成主任务；通过统一接口自主读取相关记忆 | 不例行识别记忆候选，不负责常规整理，不等待维护完成。 |
| Pi 集成层 | 注入精简索引，收集稳定回复后的可见增量，维护分支游标 | 不把全部会话或隐藏推理默认为可投递资料。 |
| built-in Agent Hooks | 定向调用入队入口 | 不等待模型处理，不递归触发自己。 |
| 后台服务/编排器 | 持久事件与状态、项目调度、进程生命周期、本地 Web | 不将进程存在等同于模型处理成功。 |
| Memory Agent | 独立判断长期价值，检索已有知识并提出受控变更 | 不批准自己的用户提案，不自由编辑索引。 |
| Memory Store/CLI | 解析、校验、条件写入、索引、提案、审计、恢复 | 不凭文件格式自动判断知识是否正确或仍有效。 |

正常链路：

1. 前台加载用户级和项目级精简索引，根据需要搜索、翻页和读取正文。
2. 一轮完整回复稳定结束，Pi 集成层提交尚未消费的可见对话增量。
3. 增量先持久化为事件，再启动或复用后台服务；前台继续主任务。
4. 同项目串行调度，Memory Agent 在新的独立 SDK 会话处理一批事件。
5. 项目级操作进入 Store 的条件写入；用户级操作形成待审批提案。
6. 保存实际 effects、完成或失败状态，供前台、CLI 和 Web 查询。

后台服务是用户级共享服务；项目队列互不混淆，项目条目仍保存在各自仓库。事件可包含任务/会话标识供审计过滤，但 Task 状态不成为长期记忆正文。

## 4. 文件协议与版本

### 4.1 条目

```yaml
---
schema: csl-memory/v1
id: project-build-entrypoint
revision: 3
type: fact
title: 项目的构建入口
summary: 正式构建通过统一 CLI 执行，不直接调用底层脚本。
sources:
  - 已确认的项目构建决策
updated: "2026-11-02T10:00:00.000Z"
deleted: false
---

## 当前结论

正式构建使用统一 CLI。

## 适用范围

适用于当前工作区的正式构建流程。

## 依据与限制

底层脚本可用于诊断，但不作为正式交付入口。
```

此例说明字段和正文组织，不要求所有类型强制使用同一组正文标题。必填元数据包括稳定 ID、正整数 revision、主要 type、单行 title/summary、非空 sources、更新时间和 deleted。正文使用 Markdown，摘要需能帮助定位适用情境，而非复制完整正文。

### 4.2 版本、修订和内容身份

| 概念 | 含义 |
| --- | --- |
| `schema` | 文件格式兼容边界；不认识的格式拒绝修改，不猜测降级。 |
| `revision` | 同一 ID 的内容修订号，每次提交递增。 |
| `hash` | 同一份完整 UTF-8 文件字节的 SHA-256，由读取接口返回。 |

完整文件 hash 不嵌入文件自身，避免自引用。章节读取返回的 revision/hash 仍对应完整条目，不是章节局部摘要；后续写入仍以完整条目为条件。

现有说明定义条目最大 256 KiB，无效 UTF-8 拒绝。该限制属于当前接口边界，调整时应检查所有读写方，不能静默截断。

已定义的协议标识包括 `csl-memory/v1`、`csl-memory-index/v1`、`csl-memory-change/v1`、`csl-memory-proposal/v1`、`csl-memory-event/v1`、`csl-memory-job/v1` 和 `csl-memory-activation/v1`。格式升级经显式迁移，不将产品版本号与条目 revision 混为一谈。

### 4.3 索引与兼容性缺口

索引现有格式包含 `schema`、`generation`、`count`；`generation` 由全部生效条目的 ID/hash 确定性生成。它是条目集合身份，不等于索引完整文件字节 hash，也不是单调递增 revision。

目标要求记忆文件具有可识别版本及文件 hash。因此不能仅凭索引已有 generation 就宣称全部完成：独立索引读取接口的完整版本/hash 契约仍须收敛并验收。未知 schema 不应被自动重写。

### 4.4 删除与恢复

删除生成 `deleted: true` 的墓碑，revision 递增，普通生效索引排除墓碑，原内容保留在历史中。恢复基于当前 revision/hash 提出新操作，产生更高 revision，不倒退版本或覆写历史。已删除 ID 的重建也不能按全新 ID 使用 revision=0 绕过旧条件。

## 5. 检索与渐进式披露

两级记忆统一采用“索引 → 搜索/翻页 → 条目/提纲/章节”的读取路径。返回结果应包含总量与下一页信息，不能把预算截断伪装成完整集合。

现有 CLI 示例：

```sh
csl-agent-kit memory list --scope user --query "构建偏好" --offset 0 --limit 20
csl-agent-kit memory list --scope project --query "构建" --limit 20
csl-agent-kit memory list --scope project --query "正文关键词" --full-text
csl-agent-kit memory read project-build-entrypoint --scope project --outline
csl-agent-kit memory read project-build-entrypoint --scope project --section "适用范围"
```

列表返回 ID、type、title、summary、revision、hash，以及 `total`、`offset`、`limit`、`nextOffset`。章节标题不唯一时不能猜选，应先看提纲或全文。

- Task Agent 和 Memory Agent 均可自主、并发读取；读取不排队，不要求后台服务或模型在线。
- 默认搜索标题、摘要等元数据，全文搜索是显式扩展；当前无语义排名。
- type 是辅助线索，不是排除相关记忆的硬过滤。
- 当前实现为避免落后索引漏读，会从条目解析列表。这实现的是 Agent 上下文渐进加载，不是底层零正文扫描或数据库级检索优化。
- 一次跨条目列表不是全局事务快照；每条目原子替换与写入 CAS 分别承担其一致性边界。

冲突处理不采用“项目永远覆盖用户”的简单规则：当前明确指令优先于旧记忆；项目硬约束与事实以正式权威来源为准；用户偏好在不违反这些约束时应用；来源冲突需查证，不能仅按更新时间决定。用户级纠正仍经提案。Memory 是证据线索，不是最高优先级指令层。

## 6. 条件写入、事务与恢复

### 6.1 变更接口

以下使用现有 CLI 请求形状，而不是原聊天中用于说明概念的扁平 `expectedRevision/expectedHash` 伪接口：

```json
{
  "id": "project-build-entrypoint",
  "operation": "put",
  "expected": {"revision": 3, "hash": "<完整文件SHA256>"},
  "reason": "构建入口已按确认决策调整",
  "source": "可追溯的决策或会话位置",
  "content": {
    "title": "项目的构建入口",
    "summary": "正式构建通过统一 CLI 执行。",
    "type": "fact",
    "sources": ["已确认决策"],
    "body": "## 当前结论\n\n正式构建使用统一 CLI。"
  }
}
```

全新 ID 的预期为 revision=0、hash=null。已有或墓碑 ID 必须使用读取结果。删除使用 `operation: delete`，不提供 content。校验失败不能转为强制覆盖。

### 6.2 提交顺序

Store 在作用域写锁内执行：

1. 检查并收尾可恢复的 pending 事务，重新读取目标条目。
2. 校验预期 revision/hash、操作和内容结构。
3. 持久化 prepared 审计记录及 pending 标记。
4. 原子替换条目。
5. 生成并发布索引。
6. 将审计标为 committed，更新关联提案状态。
7. 删除 pending 标记，返回提交信息。

过期内容返回 `CONFLICT`，调用方重新读取并判断，不盲目重试。发生 `RECOVERY_REQUIRED` 时，修改可能已经提交；必须检查审计和实际内容。

### 6.3 崩溃恢复

这是可恢复的多文件协议，不是跨文件原子事务。恢复根据实际条目字节判断：

| 实际状态 | 恢复方式 |
| --- | --- |
| hash 等于 beforeHash | 标记中止/未提交，清理可判定的 pending。 |
| hash 等于 afterHash | 补齐索引、审计和相关收尾。 |
| 两者都不等 | `RECOVERY_CONFLICT`，停止并要求对账，不覆盖未知新内容。 |

只可自动回收能够证明同主机持有进程已死亡的 writer 锁。不能仅因超时抢占活跃、跨主机或未知锁；恢复锁本身遗留也不能随意删除。

### 6.4 整理与多条目操作

项目级可以合并重复、修订过时内容、清理空内容，但必须保留理由、来源、前后差异及恢复能力。不因近期未使用删除，不丢失有效独有信息。

当前没有跨条目全局事务。建议后续整理实现采用“先写入并核验保留内容，再墓碑化被替代条目”的保全顺序；它是原设计的实现建议，不是已完成的自动整理算法。中断时宁可暂时重复，也不能先删掉唯一知识。

## 7. 用户级审批与历史恢复

用户级 put/delete 直接提交返回 `APPROVAL_REQUIRED`。标准流程：

1. Agent 提交确切内容、理由、来源及预期基线，Store 保存提案。
2. 有效记忆和派生索引保持原内容。
3. 用户查看前后差异与理由，明确批准或拒绝这个提案。
4. 批准时同时核对展示的 proposal digest 和目标条目的 revision/hash。
5. 提案或基线改变则拒绝提交，重新读取并准备提案；旧授权不转移给新内容。

CLI 的 approve/reject 要求交互确认动作与提案 ID，没有通用 `--yes` 或管道自动批准入口。Web 提供明确的批准/拒绝按钮，并绑定所展示内容。Memory Agent 不提供审批工具；Agent 自行启动伪终端也不构成用户授权。

恢复入口根据 committed 历史记录生成恢复提案：恢复到该次事务前内容，采用当前预期 revision/hash，经批准形成新的变更。当前 CLI 的 restore 对项目级也先生成提案，不应把“项目可自动维护”误写成“restore 命令立即回滚”。用户级恢复和删除始终受用户授权约束。

权限是 Prompt/CLI/UI 工作流协议，不是本机安全沙箱。本机进程若有直接文件或内部 API 权限仍可绕过；不能宣称技术上绝对只能由人修改。

## 8. 事件、队列与幂等边界

### 8.1 事件结构

```json
{
  "schema": "csl-memory-event/v1",
  "workspace": "<项目真实目录>",
  "session": "<会话标识>",
  "eventKey": "<增量终点标识>",
  "task": "<任务ID或null>",
  "messages": [
    {"role": "user", "text": "可见用户消息"},
    {"role": "assistant", "text": "可见助手回复"}
  ]
}
```

只采集可见 user/assistant 文本，不采集隐藏推理或完整工具输出。当前接口最多200条消息、128 KiB；按消息边界分批，单消息超限明确报未入队，不能静默截断。

事件身份绑定 workspace、session、eventKey，内容再绑定 hash：同身份同内容复用已有事件；同身份不同内容返回 `EVENT_CONFLICT`。先保存事件、再保存作业状态；两者之间崩溃时可由事件重建缺失作业。

### 8.2 作业状态机

| 状态 | 含义与后继 |
| --- | --- |
| queued | 等待调度，获得项目执行槽后进入 running。 |
| running | 保存尝试次数、实际模型及 effects；成功进入 completed，失败进入 failed，停止或丢失进程进入 interrupted。 |
| completed | 本批正常结束；不表示必然新增了记忆，也不等于整个项目记忆正确。 |
| failed | 失败原因可见，可能已有部分效果；检查后显式 retry。 |
| interrupted | 中断结果可能不完整；检查实际 effects 后显式 retry。 |

服务重启把遗留 running 标记为 interrupted，不自动再次请求模型。retry 保留 effects，而不是假设上一轮没做任何事。

### 8.3 调度与去重

同项目多会话共用串行维护队列，不限制前台任务并发。不同项目可并行，当前调度上限为两个项目。一个项目最早的失败/中断事件阻挡其后续事件，其他项目继续。

事件去重不等于全部操作 exactly-once。相同事件操作可通过审计来源标识去重；模型重试可能产生不同但语义相似的操作，仍需检索、CAS、effects 和人工检查防止错误重复。模型调用失败、费用边界或不明提交结果不能被自动重试掩盖。

## 9. 独立 Memory Agent

### 9.1 会话生命周期

通过 Pi SDK 的 `createAgentSession()` 创建独立内存会话，不打开交互终端、不执行嵌套 `pi --print`。每批创建新上下文，只提供未消费增量、专用提示词和按需读取能力，处理结束释放会话。持久权威是事件、状态、记忆和审计，不是不断增长的 Agent 对话。

资源加载器不加载主任务环境的扩展、Skills、Hooks 或上下文文件，防止递归维护。可以按需查阅相关来源；不继承主任务完整历史或隐藏推理。

### 9.2 模型选择

优先级：Memory 独立 provider/model 配置 > Pi 用户级保存的 `defaultProvider/defaultModel`。

```sh
csl-agent-kit memory model show
csl-agent-kit memory model set openai-codex/gpt-6-astra
csl-agent-kit memory model reset
```

这里的 set 仅是语法示例，不将该模型永久写成产品默认。reset 恢复读取 Pi 默认，不复制一次当前值为固定覆盖；不跟随前台 session 临时模型切换，也不修改 Pi 设置。默认缺失、模型未注册、身份不符或请求失败都明确报告，不静默换模型。

现有实现使用 Pi SDK 1.4.0 系列 API，并检查 `ModelRuntime` 能力；配置能解析不证明凭证和实际调用可用。已有源码关闭 SDK 自动重试与自动压缩，单批五分钟超时后报告可能已有的部分效果；这些是当前实现参数，不是已覆盖所有故障的证据。

### 9.3 工具与维护判断

允许源码只读工具 `read/grep/find/ls`，以及 `memory_list/memory_read/memory_apply`。没有通用 shell、普通 edit/write、用户批准、迁移或激活入口。只读工具本身不等于严格目录沙箱。

Agent 保存长期有据的信息：稳定事实、明确长期偏好、有适用条件的经验、可再查阅的参考入口。不保存当前进度、猜测、临时运行值、认证材料、隐藏推理或为了证明工作而生成的摘要。

每次变更要说明改了什么、为什么改、依据是什么、替代什么。项目正式规则和决策仍以权威来源为准，修改记忆不等于修改正式规则。工具失败不能被最终自然语言“成功”覆盖。

## 10. 后台服务与 Pi 接入

### 10.1 生命周期与降级

用户级本机服务按需启动并复用，采用独立 detached 进程；任务会话或终端退出后仍可处理已持久化事件。显式停止中断活动批次，保留效果和状态供检查。

服务不可用时仍应允许有效本地读取，并保存能够落盘的维护事件；无法保存时明确报告未入队，不能承诺必定自动补处理。模型失败不默认阻断主任务，也不换模型。状态需区分：启动已请求、实际监听就绪、事件已持久化、作业完成。

### 10.2 Hook 与游标

现有 Pi 入口使用稳定结束事件 `agent_settled`，不是每个低级 `agent_end`。定向执行 `inner:memory-maintenance`，不重复运行其他 stop hooks。

每个分支游标绑定工作区和最后成功入队的 entry ID。只有确认事件持久化且内容 hash 一致才推进；部分分批成功时保留已推进位置，下次继续剩余增量。游标失效需报告，不猜测跳过。

首次激活从当前位置开始，不默认回灌整个历史。每轮开始注入两级精简索引，正文仍自主读取；轮询只展示服务、失败、待处理和未入队状态，不把入队当作维护完成。

### 10.3 激活边界

现有 bridge 检查 `csl-memory-activation/v1` 标记。开关检查已有代码不等于激活流程完成；不得手工写标记绕过迁移、消费者切换、失败恢复和验收。

新项目初始化、已有项目切换前检查、准确激活对象及回退路径仍需实施任务补齐。本设计落盘不启动真实项目服务，也不激活自动维护。

## 11. Web 审计、授权与隐私

本地 Web 和 CLI 应提供：

- 按项目、会话、任务查看队列、尝试次数、模型、失败原因和实际 effects。
- 查看自动变更前后内容/差异、理由、来源与历史。
- 查看确定用户提案并明确批准/拒绝。
- 从历史发起恢复提案，保持授权和当前版本校验。
- 显示部分失败，不能只展示模型最后一句总结。

现有安全设计为 loopback 监听、随机 bearer token、Host/Origin 检查、不开放跨域 API、动态内容文本渲染及 CSP。面板入口携带的 token 不应分享；这些约束不等于防护本机所有进程。

可见对话也可能包含敏感信息，模型处理会将增量及按需读取材料发送给所选提供方。“不要保存密钥”的提示词不是通用脱敏器；本地文件权限不等于加密。事件、审计、备份的保留与清理策略仍待定，当前不能宣称已有自动生命周期管理。

HTTP 200/401/403 只能证明特定接口响应，不能替代浏览器点击、提案展示一致性、批准/拒绝、恢复和可访问性的实际验收。

## 12. 迁移、旧机制退出与正式切换

### 阶段 A：完整预览

读取旧 Context/Lessons 全部源内容并固定源 hash；包括前言、未索引章节及围栏之外的真实标题，不遗漏旧索引无法检索的内容。每个单元明确 import 或 archive，并记录理由和依据。archive 仅表示保留完整源备份、不建有效条目，不等于删除源。

### 阶段 B：批准精确预览后导入

用户核对具体清单，批准绑定该预览摘要。执行前重核源集合/字节、目标冲突及范围；先保存完整预览和原文，再经正常 Store 条件写入与审计导入。仅导入 project，不提升到 user。

相同预览重复应用不得重复创建条目；中断后从实际审计识别已提交但尚未登记的效果。源变化拒绝继续，不能吸收未批准的新内容。部分失败报告已发生效果，不声称全量回滚；恢复仍不能覆盖后来的合法修改。

### 阶段 C：替换所有消费者

逐一核对旧 Skills、规则、manifest、Hooks 及所有受影响宿主的 Context/Lessons 消费者：读取改走 Memory，例行维护从 Task Agent 移到后台，清除失效引用和长期兼容维护分支。首版只有 Pi 自动接入不意味着共享旧机制可留下悬空引用。

完成前台读取、后台维护、用户审批、审计恢复、故障降级和必要独立审查。不得以一次成功模型调用代表全部可靠性。

### 阶段 D：正式切换与旧资料处置

展示准确切换对象、旧资料处置和影响，保留明确授权；验证恢复路径后再激活。批准导入不等于批准删除、停止旧机制或激活。目标终态消除双重权威，过渡期保留原文件不是长期双轨设计。

最终验收是授权、数据完整性、恢复、非阻塞运行和旧体系退出同时成立，而不是后台进程能够启动。
