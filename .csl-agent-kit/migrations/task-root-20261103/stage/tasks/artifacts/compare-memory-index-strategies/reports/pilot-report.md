# Memory 索引对照试跑报告

## 结论边界

已执行36次真实模型请求，没有失败重试，未启动432次正式实验。两组均18/18答对；当前题集不能证明两种方式在困难问题上的质量相同。

在本次模型自主选择读取方式的条件下，分页组总体token更少，完整索引组总体中位耗时更短。50文件时完整索引组token略少，200与1000文件时分页组优势明显。不能据此宣称分页在所有规模、所有检索策略下更优，也不能宣称已证明完整索引加search-first不如分页。

## 实验设置

- 模型：openai-codex/gpt-6-astra；API为openai-codex-responses，thinking=medium。没有静默切换模型；SDK没有提供不可变的后端模型修订号。
- 每种方法18次：6类题×50/200/1000文件三个规模，每题每规模单次。每个规模的文件数是user与project两级合计，两级各半。
- A使用当前生产store.indexPages产生的4000字符分页；B把相同条目行放入完整索引。条目正文、顺序、title/summary/type/revision/hash逐项相同。
- 两组共用同一提示，仅给出索引路径，不预注入索引。使用相同SDK read/grep/find实现，以实际路径检查限制在各自合成语料中；无shell、写入、网络搜索或其他Agent工具。
- 每次全新内存会话，关闭重试与自动压缩；配对顺序交错，全部串行。每请求180秒、60次工具上限，单次模型响应maxTokens=4096；累计目录估价25美元时停止后续请求，这是软阈值，不是实际账单硬上限，本次未达到。
- 正式原始记录、运行器、题目及答案冻结，运行前后核对数据hash。无真实记忆、凭证和隐藏推理正文进入实验产物。SDK鉴权凭证仅用于正常模型访问，未暴露给检索工具。

## 总体结果

| 指标 | A：分页 | B：完整索引 |
| --- | ---: | ---: |
| 严格成功 | 18/18 | 18/18 |
| 全部请求token总和 | 295,904 | 1,138,743 |
| 平均token/成功任务 | 16,439 | 63,264 |
| 非缓存input token | 136,633 | 460,352 |
| cacheRead token | 155,904 | 675,328 |
| output token | 3,367 | 3,063 |
| 工具调用总数 | 78 | 66 |
| 工具返回字节总数 | 177,322 | 935,967 |
| 端到端耗时中位数 | 13.58秒 | 11.08秒 |
| p95（最近秩） | 42.36秒 | 40.04秒 |
| SDK目录估价 | $1.69 | $5.43 |

总token包含各模型轮次重复上下文及缓存读取，并非唯一正文token数；缓存token有成本，不能既计入total又额外加一次。SDK返回reasoning=0仅按返回值保留，不证明服务端没有推理开销。

A的总token约为B的26.0%。按六个问题模板聚类、保留同题三个规模关联的10000次bootstrap，A/B token比的探索性95%区间约为[0.222, 0.301]。只有六个模板，且均成功，不将该区间当作质量非劣或普遍优势的证明。未因全部成功而报告误导性的“质量差异精确为零”。

每格只有6次请求。50文件时，分页增加的查找轮次可能抵消首页较小的收益；token与目录估价不完全同向，因为缓存比例不同。耗时受网络、服务端排队和调用轮数影响，不能由一次试跑给出稳定延迟保证。

## 轨迹解释

两组实际都先read索引，而非先grep。A首页较小，未找到目标时常对正文目录grep；B首次read带入更多内容，在大规模时触及SDK单次输出截断后再检索。B因此有时减少工具轮数，但把更长索引上下文带入后续模型调用。

这支持一个有限的观察：当前默认行为下，小首页能约束首次read的成本。它不能回答“如果明确要求先grep完整索引，再只read相关段落，是否更好”。试跑期间没有为B临时增加技巧或更改提示；相关策略须另设冻结对照，不得替换原试跑记录。

## 质量核对与限制

预先固定了准确值、必要来源、范围条件与拒答标志。36个最终JSON均逐项满足标准答案和必要来源集合；6个不存在题均拒答，其余30个没有错误拒答。实际工具轨迹均在合成根内，没有工具错误、超时或预算耗尽。

局限：

1. 每类只有一个模板、每规模单次，容易出现天花板效应；语义题仍含精确对象名，不代表无关键词语义召回。
2. 无真实业务语料、深层矛盾、多版本知识或动态写入；本次不能外推这些场景。
3. 未测试生产启动时预注入首页；本实验刻意不注入，以隔离文件表示差异。
4. 保留provider自然缓存，未声称能够清空；每次新会话不等于服务端没有缓存。
5. 严格评分针对离散虚构标识与来源，不以模型自评代替标准答案；没有需要语义裁判的开放答案，因此没有新增裁判调用。
6. 冻结运行器的初步report把偶数样本的上中位值作为medianMs。自检发现后保留原始产物，新增analyze.cjs独立重算标准中位数（中间两值均值）；本报告以analysis.json为准。未修改冻结运行器或重跑模型。

## 费用与后续决策

本试跑SDK目录估价合计$7.122582，不是订阅账户实际扣费。按相同题型/规模/缓存分布线性外推432次约$85.47；难度与模型轮数改变时费用也会变化，不是报价或保证。以上不含任务主Agent和独立审查消耗。

建议先据试跑修正正式题集：增加不能用精确对象名直接命中的问题、正文限定条件和相近干扰项；另外明确是否要比较search-first策略。当前结果不足以取消分页，也不足以证明必须分页。未自动运行正式实验或修改Memory产品。
