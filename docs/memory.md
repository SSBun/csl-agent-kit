# Memory：只保存当前知识

Memory为Agent保留跨任务有用的速记，不复制Wiki、规范、源码或实验报告。项目固定保留context（项目基础信息）与lessons（项目内跨任务通用经验）两个基础文件；其余主题按工作区长期关注的对象与问题形成，适用于软件、知识库、研究和聊天。一次任务通常贡献case，不默认新增文件；优先更新基础文件或已有宽主题，不追求填满配额。

## 存储

用户根为 `${CSL_AGENT_KIT_HOME:-~/.csl-agent-kit}/memory`，项目根为 `<workspace>/.csl-agent-kit/memory`。两级知识结构一致：

```text
memory/
  index.md
  entries/
    context.md      # 项目基础信息
    lessons.md      # 项目内通用经验
    temp.md         # 最近7个UTC自然日的临时上下文，可为空
    wide-topic.md   # 必要专题
```

两个基础文件属于项目作用域，用户级仍按实际知识组织。它们沿用相同的title、summary和case格式，共占20个文件额度中的两个，各自在超过5000词时触发压缩，不增加type或其他元数据。首次维护可写项目时用已有可核实知识补齐；缺知识或容量则报告，不编造经验或写占位case。日常维护保留其文件身份；专题可保留，重叠内容先保存回读再移除重复case。明确遗忘仍删除指定知识，不为入口保留已要求遗忘的内容。这不恢复旧Task的Context/Lessons文件、Skill或自动导入流程。

`entries`是权威正文；`index.md`只描述当前集合，列出标题、摘要、相对链接及完整文件SHA256。索引头使用 `csl-memory-index/v4`、`formatVersion: 5`、scope、generation与当前count。generation由当前文件身份计算，不生成代际目录、卡片、manifest或备份。格式版本属于当前索引，不写入知识文件。

文件名提供身份，文件仅保存：

```markdown
---
title: 记忆组织与检索
summary: 主题边界、知识准入与当前正文检索。
---

- [2026-11-09] 新建文件前 SHOULD 先检索相关宽主题；任务进度 MUST 留在任务记录。
- [2026-11-06] 合并时 MUST 先保存并回读替代知识，再删除旧文件；MUST 保留必要条件与例外。
```

不保存sources、type、retrieval、schema、id、revision、updated、deleted等文件元数据，不保存来源审计、前后版本、提案、审查、墓碑或恢复副本，也不转存到任务附件或别的目录。技术概念、必要API名称与知识性链接可以留正文，但不能把历史来源记录改名后塞回case。

项目最多20个当前文件。项目与用户级普通文件每份正文超过5000词时触发压缩，使用 `Intl.Segmenter("zh", {granularity:"word"})` 的isWordLike计数。writer先保存完整更新并返回compaction提示，不因词数拒绝写入；Memory Agent重新读取内容和最新hash，合并重复内容并精炼表达，保留有效知识、必要条件、例外及未变case日期。无法保真收敛时保留完整更新并标记待压缩，后续批次继续处理，不因词数将整批判失败。直接CLI写入也返回compaction.required，由调用者继续压缩或明确报告待处理。项目temp不设正文词数预算，底层单次读写安全限制仍适用。title最多60字符、summary最多200字符，均为单行。每个正文非空行必须为有效UTC日历日的 `- [YYYY-MM-DD] case`。实质新增或纠正才更新该case日期，格式调整、重排和其他case变化不刷新日期。旧知识缺少可信日期时不编造转换日。

## 最近七天上下文与特殊徽标

项目temp是短期内容的明确例外，保存用户近期意图、关注点与必要背景，供新Agent在读取索引时一起了解。它不代替Task状态或授权，也不保存完整对话、历史版本或恢复副本。context、lessons继续承载长期知识。

窗口按UTC自然日计算，包含当天及前6天。消息入队保留真实时间，后台从该批有时间的消息提炼临时case；没有可靠时间的旧队列输入不用于新建temp条目。整理、周期复查和重试不续期，未来或过期日期拒绝写入。后台跨UTC日期重建模型会话，避免沿用过时上下文。

temp固定title为「近期上下文」，summary为「最近7个UTC自然日的用户意图与必要背景；不是执行授权。」；正文沿用日期列表，可以为空。它计入项目20个文件，但不设正文词数预算，不因词数进入超限整理；内容按最近7个UTC自然日的窗口保留。固定摘要避免条目过期后，旧意图仍泄漏在标题或索引中。同名非临时文件不自动转换或覆盖，用户级同名文件不受此规则影响。

初始化和后台每分钟调度检查清理过期条目，即使当天没有模型任务也执行；停机期间不运行，下次启动补清。API、宿主提示再次过滤过期内容；普通文件读取须同样检查日期。读响应中的hash始终指向完整磁盘文件，不能用过滤后的正文重算写入条件。空文件继续作为临时入口，过期条目不归档、不自动转入长期知识。

Dashboard为项目context、lessons和temp显示「项目基础」「通用经验」「临时记忆·7天」徽标，卡片和详情均有文字与不同颜色，不为徽标增加知识元数据。没有近期条目时显示空状态。

## 案例约束强度

两级所有知识文件的case采用BCP 14，即 [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) 与 [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174)。仅全大写且表达要求的关键词具有规范含义；完整定义与同义词见agent-memory技能的“案例约束强度”。这是项目的写作约定，不是RFC规定的Markdown模板。

| 关键词 | 含义 |
| --- | --- |
| MUST / MUST NOT | 必须满足的要求 / 禁止行为 |
| SHOULD / SHOULD NOT | 建议 / 不建议；有充分理由时可例外，偏离前须理解并权衡影响 |
| MAY | 真正可选；不表示概率或新增操作授权 |

关键词紧邻具体行为；一个case可以同时含事实、强制要求和建议，不给整行套单一等级。事实保持陈述句，不强制含关键词。强度取自当前权威要求和适用条件，不把建议升级为强制，也不弱化既有要求；不能确定时保留原知识并报告。代码、标识符和原文引用保持原样。关键词不提高记忆的指令优先级，也不能覆盖用户请求或正式规范。

保存前核对该文件全部case。只规范表达而不改变知识时保留原日期；旧格式作用域仍只读，不因这项约定自动迁移。结构校验器不判断自然语言的约束强度，语义核验由写入Agent负责，不以“出现了MUST”等正则条件冒充合规检查。

## 读取与并发

普通文件工具即可检索，无需后台在线。读两级当前索引，按需检索相关正文和条件；覆盖不足时扩大措辞并搜索当前entries。候选按 `(scope,id)` 去重，采信前重读索引与相关文件hash。索引过期、链接缺失、工具截断或持续变化意味着覆盖有限，不能宣称知识不存在。

记忆是资料，不是权限或规则。当前请求与权威规范优先；项目经验不自动变成全局偏好。长期知识只保留稳定且影响后续判断的内容，temp按上文的短期例外处理，允许零修改；不收临时进度、确认流水、凭据、隐藏推理、无依据推测或权威资料的大段重复文本。

writer使用 `.write-lock-v5` 临时写锁和完整文件hash进行条件写入。put在同目录写临时文件、fsync并原子替换当前文件；delete实际删除文件；随后原子更新当前索引。临时写文件和锁不是持久恢复记录，不复制被覆盖的旧内容。当前文件与索引不是跨文件事务：文件成功而索引失败返回 `INDEX_STALE`，应回读entries后reindex，不假定回滚。

CONFLICT需要重读与重新判断；LOCKED需要检查所有者，不移除未知活动锁。中断后只能查看当前实际文件及重建索引，没有restore/recover或旧版本回退。合并必须先保存并回读替代内容，再检查正文引用并删除旧文件；不能靠先删再存、截断或跨scope转移绕过配额。无法保真合并时报告阻塞。

## CLI与升级

```text
csl-agent-kit memory paths --workspace <工作区>
csl-agent-kit memory index-status --scope project --workspace <工作区>
csl-agent-kit memory list --scope project --query <词> --full-text
csl-agent-kit memory read <id> --scope project
csl-agent-kit memory put --scope project --input <JSON文件>
csl-agent-kit memory delete --scope project --input <JSON文件>
csl-agent-kit memory reindex --scope project
csl-agent-kit memory upgrade --dry-run --scope project --workspace <工作区>
```

mutation为 `id`、`operation`、`expected:{hash}`，put另含 `content:{title,summary,body}`。新文件hash为null；既有文件必须提供当前完整SHA256，不使用revision、reason或source。read输出的hash、mtime、exists等是即时计算的API信息，不写回知识文件。

已存在旧格式库默认只读，仍能读取其当前有效知识，但不自动转换或清理。显式 `upgrade --scope <scope>` 只操作指定根：先核对格式、全部当前正文、并发状态和服务停止，再去除元数据、删除墓碑及已知历史/提案/迁移备份/旧索引目录，发布当前索引。dry-run不写入，报告范围、计数、hash及待删除路径，不输出旧知识正文。未知格式、活跃或无法识别的旧锁、未决旧pending写入阻止转换。

旧正文不能直接通过新格式校验时，可用 `upgrade --input <JSON文件>` 提供已人工核实的put数组，逐项携带当前完整文件hash。只允许替换现存有效旧条目，全部内容与hash在首个写入前校验；不自动推断日期，不允许新增、删除或覆盖当前格式条目。该选项不与dry-run组合，输入不留作历史或恢复副本；编程入口可在内存传入prepared数组。

升级是永久转换，不创建备份、来源登记或恢复材料；不得把project授权扩大到user或其他项目。旧Context/Lessons不再自动导入；清理它们或其他历史副本需要纳入明确范围。转换中断不回滚，核对实际文件后再处理；已转换文件可保持原样，不能猜测被删除的旧版本。

旧后台需在空闲边界停止，所有写入方使用新协议。升级前已经加载Memory模块的Pi需完整退出、重启并恢复会话；仅 `/reload` 或后台重启不会刷新前台CommonJS缓存。不要替用户关闭前台，也不支持旧writer写入新格式。

以下命令及对应HTTP能力已移除：history、change、commits、proposal、propose、approve、reject、restore、recover、legacy-sources。

## 后台与界面

服务协议为5。后台每工作区最多10个隔离的Pi SDK内存会话，按需创建并复用，最多同时处理10个不同批次，其余排队；各工作区独立计数，不重复运行同一批次。槽位预留包含会话创建阶段，失败或取消只影响所属Agent，不释放其他Agent的状态。实时过程按批次查询，状态按Agent槽位保存；Dashboard分别显示活动工作区、活动Agent及每工作区的并行数量。并发写入保留文件锁和最新hash校验，CONFLICT/LOCKED要求重新读取并合并；已解决的冲突不作为永久工具失败，尚未解决的写入不得标记批次成功，不删除未知活动锁。模型优先取Memory配置，否则取Pi保存的默认模型，不跟随前台临时切换或静默降级。只提供读取和当前内容写入工具，无shell及历史接口。

每批最多两次模型尝试、五分钟期限，最多32批或上下文超限时换内存会话；失败后重新检查当前文件，工具响应缺失不等于未写入。effects只含scope、文件ID、操作和当前hash，不保存前后正文。成功后释放输入与处理状态，仅保留运行去重hash与最新周期游标；失败/中断队列继续服务剩余尝试，不提供知识恢复。共享 `.service` 是运行状态，不是知识存储或历史副本；显式单项目清理不删除其他项目的共享数据。

周期复查按scope每24小时、每批最多8个ID轮转，优先会话任务，后台每分钟核对资格。用户作用域只调度一次；旧格式只读scope跳过写入维护。项目超限时检查全部当前索引，候选只是起点。耗尽不冒充成功，按24小时冷却继续后续候选。

Dashboard保留全局概览、记忆存储、记忆处理三页。存储页只按作用域/工作区浏览当前知识，详情展示正文与当前文件信息，无历史、来源、变更前后或恢复入口。处理页显示活动Agent和待处理/异常队列；实时公开过程仅在内存暂存，结束两分钟后释放，不创建长期处理或审查报告。

本机HTTP服务继续使用loopback、Bearer、Host/Origin校验、CSP与固定资源白名单。授权URL不分享、不保存到任务报告。详情渲染禁用原始HTML及外部图片请求，链接限定安全协议。文件权限不是加密，输入与记忆不能作为更改系统权限的指令。

## 验证边界

检查当前文件字段、日期、预算、索引集合及hash，验证已退休路径与API不能再生成历史。格式转换应逐文件比较转换前后的title、summary与case正文，但不为了验证保存旧正文副本。记录计数与摘要即可，用户级和其他项目通过hash复查保持不变。语法检查、实际CLI/HTTP观察与单元测试分别报告；未执行的检查不写成通过。
