# 场景执行路径与结论证据评估

本套件检查 Agent 是否从用户场景定位实际入口、追踪关键执行路径，并按证据限定结论。材料位于项目评估根，不进入共享 Skill 分发。共同原则由 [Contract](../../skills/meta/agent-hooks/references/csl-agent-kit-contract.md) 的 Execution Evidence 维护，技能只补充自身操作要求。

## 材料与使用

[cases.json](cases.json) 含最小化的合成代码、用户问题、预期观察及对照变体。代码仅作为待检查源码，不导入、不执行。每例的 `files` 是独立虚拟项目；对照例以 `contrast.replaceFiles` 替换同名文件，其余文件保持不变。不要将不同例的同名文件混在一个项目。

获得真实模型回放授权后，复用宿主现有工具和独立上下文：

1. 将单个变体的文件放入隔离临时目录，记录实际目录及文件摘要。模型只接收 `prompt` 与对应源码目录，不提供预期答案、对照代码、标注或其他场景。
2. 基线与修改版使用相同模型、工具和权限，分别加载其真实 Contract 与相关 Skill。按问题类型选择 tldr、repo-map、bug-fix、task 或 task-review，不要求每次加载全部技能。记录实际版本和加载来源。
3. `priorMessages` 仅用于第七例的历史前提场景，按标注的角色顺序提供；不得以作者解释替代这些可见消息。其余例从空上下文开始。需要实施的例在真实 Task 确认边界回复目标确认后继续观察，不将 Task 确认计为无关等待。
4. 保存可见答案、实际读取路径、工具观察和检查版本。只记录行为证据，不索取或保存内部思维链。使用已有宿主输出捕获方式；若需持久化，生成结果放入本目录忽略的 `results/`，不提交完整会话。
5. 由评估者对照 `expected` 与 `failIf` 判读；这些是待人工复核的初始标注，保持 report-only。代码包含提示词关键词或回答出现固定术语均不代表通过。

这些步骤是回放说明，不是新增 runner。本次提供材料不等于已运行回放，也不证明真实 Agent 行为改善。场景的代码差异是行为原因，不能让模型根据对照标签猜答案。

## 判读

- **错误肯定／错误否定**：结论是否超出实际检查的场景及版本；是否把局部搜索当作不存在的证明。
- **关键路径核验**：实际读取是否包含正确入口与足以改变答案的分支、状态或消费者。允许多种有效查找顺序，不强制固定工具次数。
- **反证纠正**：是否修正主结论并在依赖操作前处理错误前提；不能只在末尾增加免责声明。
- **不确定边界**：入口或运行证据缺失时，是否给出已知事实与具体未知；静态推演不等于运行成功。
- **简单路径成本**：对照例证据充分时是否直接回答。记录读取文件数、工具调用数及无关确认／审查，不设置脱离宿主条件的固定阈值，也不以少读代码奖励遗漏。

分别报告各项及对照例退化，不能用一个总分掩盖准确性与成本之间的变化。修复、mock 或 Reviewer 回放还需观察对应技能职责，普通问答回放不能代替这些验证。

## 本次验证边界

JSON 解析、案例字段及对照文件完整性、文档链接、Skill Quality 和 Hook 读取输出可由确定性命令检查。真实模型回放、跨模型稳定性、真实业务运行和所有现有宿主会话重新加载需要分别观察，不得由上述静态检查推定。本次未运行单元测试、项目测试或真实模型回放。
